## SCP Usage

- **Type**: Pure LLM-agent skill, **zero external key required** (OpenAlex + Crossref both open APIs). Phase 1-5 zero external model; no MCP server.
- **Invocation**: Called by `querystrategist` (main Skill), or directly by the user.
- **Runnable helpers**: See `scripts/harvest.py` (OpenAlex harvest + Crossref verify; dependency bootstrapping via `scripts/requirements.txt`).
- **Data flow**: Reads/writes the shared Pipeline Context across the Step 0-2 workflow.

## Conditional Dependencies

本 Skill 默认**零密钥、零配置即可运行**——OpenAlex 与 Crossref 均为开放 API，无需申请任何 Key：

1. **OpenAlex**（主源，收割）：`https://api.openalex.org/works`，无需 key。
2. **Crossref**（验证器）：`https://api.crossref.org/works/{doi}`，按 DOI 逐条回查验证，无需 key。可选 `--mailto` 以接入 polite 池（10 req/s），缺省即匿名 public 池（5 req/s），不影响功能。
3. **requests==2.32.5**：唯一第三方依赖，`harvest.py` 首次运行自动安装（或 `pip install -r scripts/requirements.txt`）。

> **已移除（V2.0）**：Semantic Scholar（无 Key 共享池实测必 429，且召回增量可忽略）与 Scholar-KG（SCP MCP 检索增强）已从本 Skill 彻底删除，不再作为可选项。

## Runnable Scripts

### `scripts/harvest.py` — 文献元数据收割器（两源版）
OpenAlex 收割 + Crossref 逐条验证（Search B 通道，对应 Search Strategist V1 Step 2 的 API 收割）。零配置开跑：

```bash
# 方式一：首次运行自动安装依赖（推荐，零配置）
python scripts/harvest.py --check-deps          # 仅检查/安装依赖，验证环境就绪
python scripts/harvest.py --query "organ-on-a-chip drug toxicity" --out harvest.json

# 可选参数
python scripts/harvest.py --query "..." --mailto you@example.com   # Crossref polite 池标识
    python scripts/harvest.py --query "..." --no-verify                # 跳过 Crossref 验证
    python scripts/harvest.py --query "..." --min-year 2016 --max-year 2026
    python scripts/harvest.py --query "..." --dry-run                 # 不联网，仅检查参数/预算
python scripts/harvest.py --query "..." --per-platform 30          # 每条返回数量

# 方式二：手动预装（可选）
pip install -r scripts/requirements.txt         # requests
```

> **首次使用零配置（V1.8 保留）**：`harvest.py` 导入时自动检测缺失依赖并用 `python -m pip install` 一键补齐（安装前自动清除可能指向本地死代理的 `*_PROXY` 环境变量）。离线/自管环境可设 `HARVEST_NO_BOOTSTRAP=1` 关闭自动安装。

**输出结构（V2.0 新增验证分层；V2.1 每条记录附带 OA 字段）**：
```
{
  "query": "...",
  "openalex": [...],        # 原始收割记录（每条含 verification 字段；V2.1 起含 is_oa / oa_status）
  "verified": [...],        # ✅ Crossref 验证通过（title 相似度≥0.8 且年份差≤1）→ 可信候选
  "unverified": [...],      # ⚠️ 无 DOI / 验证瞬时失败 → 保留供人工参考
  "dropped": [...],         # ❌ 验证不通过（title_mismatch / year_mismatch / doi_not_found）→ 疑似幻觉/错配，剔除
  "statistics": {"harvested": N, "verified": N, "unverified": N, "dropped": N, "verify_enabled": true}
}
```
每条记录字段（V2.1）：`title` / `authors` / `year` / `doi`（完整 URL）/ `cited_by_count` / `url` / `source` / **`is_oa`** / **`oa_status`**（open/gold/green/hybrid/bronze/closed；收割时 OpenAlex 原生附带，不再逐篇回查）。

**验证逻辑（去幻觉核心，V2.0）**：
- OpenAlex 每条记录自带 DOI（完整 URL 形式），提取裸 DOI 后回查 Crossref `GET /works/{doi}`；
- 比对 Crossref 返回的 title（归一化后 SequenceMatcher 相似度 ≥0.8）与 year（|Δ|≤1，容忍出版年先后偏差）；
- 通过 → `verified`；title 或 year 明显不符 → `dropped`（附 `reason`）；无 DOI → `unverified`；单条验证瞬时网络错误 → 标记 `verify_error` 保留不武断判死；DOI 在 Crossref 404 → `dropped`（`doi_not_found`）。


# Literature Harvester

## QueryStrategist System
This skill is part of the **QueryStrategist** workflow (V2.0). It serves as the Search B pathway within **Search Strategist V1** (Step 2). It harvests literature metadata from OpenAlex and cross-verifies each entry via Crossref, providing a verified candidate list that complements the manual database queries generated by Query Crafter — and crucially, filtering out AI-hallucinated or mis-attributed entries before they reach the user.

## Description
An automated literature retrieval module that harvests literature metadata from the **OpenAlex** API (no key required, stable primary source) and **cross-verifies each entry via the Crossref REST API by DOI** (title similarity ≥0.8 and year delta ≤1). Entries failing verification are marked `dropped` (suspected hallucination/mis-attribution) and excluded from the candidate list; entries without a DOI are kept as `unverified` for manual review. The verification layer operationalizes the "harvested ≠ corpus" principle — AI-hallucinated metadata never silently reaches downstream. This module is the Search B component of the Search Strategist.

## Role
You are an automated literature retrieval and verification engine. You harvest candidate metadata from OpenAlex, cross-verify each entry against Crossref by DOI, normalize heterogeneous outputs into a uniform format, and present a consolidated list of **verified** publications. You are meticulous about data quality and always report verification statistics.

## Input Requirements
The following inputs are provided by the calling Search Strategist:

1. **Keyword Tiers** (from the Review Scope Confirmation Document):
    - Tier 1 – Species/Object: `species_terms` / CLI `--species`
    - Tier 2 – Technology/Method: `tech_terms` / CLI `--technology`
    - Tier 3 – Application/Task: `task_terms` / CLI `--task`
2. **Search Configuration**:
   - Time Span: start year and end year (from Project Configuration Profile)
   - Search Focus: `review-priority` (for V1, prioritize review articles) or `all-types` (for V2, all literature types)
3. **Results Limit**: Maximum number of results to return **per sub-query** (default: 20–25).
4. **Exclusions**: `exclude_terms` / CLI `--exclude`, applied locally to title and inverted-index abstract.
5. **mailto** (optional): Real email for Crossref polite pool (10 req/s). If not provided, the script uses the anonymous public pool (5 req/s) — no functional difference, only rate.

## Workflow (V2.0 — Script-First, Verify-Always)

**职责边界**：`scripts/harvest.py` 脚本自动完成收割、DOI 提取、Crossref 逐条验证、三态分层。LLM 的职责是：
1. 将三层关键词和排除项转化为 `harvest.py` 可执行的命令行参数
2. 向用户展示验证统计（verified / unverified / dropped 计数与原因）
3. **仅当脚本不可用**（如依赖缺失、网络封锁）时才降级为手动 WebFetch 模式

### Step 0: 初始化收割任务

向用户展示配置概要：

| 配置项 | 值 |
|:---|:---|
| 检索焦点 | Review articles / All types |
| 时间范围 | [Start Year] – [End Year] |
| 数据源 | OpenAlex（收割）+ Crossref（验证） |
| 验证策略 | 逐条 DOI 回查（title 相似度≥0.8 且 year 差≤1） |
| Key 状态 | 无需任何 Key |

### Step 1: 构造子查询并执行 harvest.py

根据三层关键词，生成 4-5 个聚焦子查询（每个子查询必须保留对象层，并选择一对技术词+任务词）。**规则与旧版 Step 1 相同**（领域锁定、负向排除、术语具体性、综述标识等规则全部保留）。

然后为每个子查询构造 `harvest.py` 命令行：

```bash
python scripts/harvest.py \
  --query "YOLO object detection cat freshness" \
  --species cat dog \
  --technology YOLO "object detection" \
  --task freshness grading \
  --exclude disease "water quality" \
  --min-year 2016 --max-year 2026 \
  --per-platform 20 \
  --out harvest_q1.json
```

**执行策略**：所有子查询独立 try/except，单个失败仅记录该子查询错误，其余照常；全部失败才报告整体失败。验证环节对每条记录独立容错，单条验证瞬时失败标记 `verify_error` 保留，不武断判死。

### Step 2: 汇总并展示收割+验证报告

读取各子查询的 JSON 输出，汇总统计，输出格式见下方 Output Format。**向用户明确说明**：`verified` 为可信候选；`dropped` 为验证不过的疑似幻觉条目（可列出几条典型 example 供用户感知验证在起作用）；`unverified` 为无 DOI 条目，需人工判断。

### 降级路径：脚本不可用时的手工模式

如果 `harvest.py` 不可用，降级为 LLM 手工 WebFetch：
1. 调用 OpenAlex `/works` API 收割（WebFetch URL）
2. 逐条按 DOI 调 Crossref `/works/{doi}` 验证（WebFetch URL）
3. 手动解析 JSON、比对 title/year、去重、合并

### Post-Retrieval Recommendations

Based on the retrieval results, provide brief guidance:

- **If verified ≥ 100**: "Excellent retrieval volume. The sub-query strategy has produced comprehensive coverage. Identify the highest-performing tech–app pairings from the detail table and prioritize those batches."
- **If verified 30–99**: "Moderate retrieval volume. Review the sub-query detail table—low-performing pairings may benefit from broader terms, removing negative terms, or extending the time span."
- **If verified < 30**: "Low retrieval volume. Your topic may be highly novel or the keyword pairings need broadening. Remove negative terms, use more general keywords, or extend time span."
- **If OpenAlex failed**: "OpenAlex harvest failed. Possible network or rate-limit issue. Proceed with manual database queries from Search A (Query Crafter) and retry harvesting later."
- **If dropped ratio high (e.g. >30%)**: "High drop ratio suggests the query surfaced many hallucinated/mis-attributed entries — consider tightening the query or relying on Search A manual queries."

## Important Notes
- **V2.0**: Search B = **OpenAlex 收割 + Crossref 验证**，Semantic Scholar / Scholar-KG 已彻底移除（零密钥、零弹窗、零 mcp 依赖）。
- **V2.0**: 验证逻辑为去幻觉核心——`verify_by_doi()` 按 DOI 回查 Crossref `GET /works/{doi}`，比对 title（归一化 SequenceMatcher ≥0.8）与 year（|Δ|≤1）；不通过 → `dropped`；无 DOI → `unverified`；瞬时错误 → `verify_error` 保留。
- **V2.0**: 依赖收敛为仅 `requests`（httpx / mcp 已移除）。
- **V1.4 新增**: OpenAlex 字段限定搜索(`harvest_openalex_filtered`)支持三块强制共现，大幅提升精确率。**关键语法规则详见下方"OpenAlex Field-Limited Search 语法规则"**。
- **V1.4**: 推荐排序策略：自算 `rel_score`（物种词数 + 技术词数 + 投喂词数 三者共存），而非 `cited_by_count`——高被引通用论文会淹没真正相关的低被引领域论文。
- **V1.3**: 脚本优先模式。优先使用 `harvest.py` 脚本执行，仅当脚本环境不可用时降级为手工 WebFetch。
- **V2.2 配额守卫**：OpenAlex 默认预算 120 次、Crossref 默认预算 60 次；连续 3 次 429 熔断，`Retry-After` 最多等待 20 秒，响应按请求参数缓存，并提供 `--dry-run` 与失败统计。命中预算后停止发起新请求并保留已完成结果。
- **V1.7 修订**: `cites:`/`referenced_works` 过滤器必须用 OpenAlex **work id（Wxxxx）**，不能用 DOI（传 DOI 报 HTTP 400 并会累积触发端点级长冷却）；先 `GET /works/doi:{DOI}?select=id` 解析。
- Both APIs index primarily English-language literature. For Chinese-language coverage, rely on CNKI queries from Query Crafter.
- This skill does NOT download PDFs; it only retrieves and verifies metadata. PDF download is the user's responsibility.

### OpenAlex Field-Limited Search 语法规则 (V1.4，V2.0 修订排除词)

当使用 `harvest_openalex_filtered()` 的 `filter=title_and_abstract.search:` 参数时，必须遵守以下规则，**违反任一即 HTTP 400**：

| 规则 | 正确写法 | 错误写法（会 400） |
|:---|:---|:---|
| **不支持括号分组** | `"cat"|"dog"|"bird"` | `("cat"|"dog"|"bird")` |
| **多词短语必须加引号** | `"computer vision"\|"deep learning"` | `computer vision\|deep learning` |
| **单 token 可裸写** | `cat|dog|bird` | 无需引号，裸写即可 |
| **\| 为 OR（组内）** | `"cat"|"dog"|"bird"` | — |
| **逗号为 AND（组间）** | `filter=A,filter=B` | — |
| **`sort=relevance_score` 必须配 `search=`** | `params={"search":"...","sort":"relevance_score"}` | `params={"filter":"...","sort":"relevance_score"}` — 必 400 |
| **⚠️ 排除词不支持 API 层（V2.0 实测确认）** | 传 `exclude_terms` 参数，脚本**本地**按标题和 inverted-index 摘要后置过滤 | `title_and_abstract.search:-"cat"` — `-` 前缀**静默失效**（不报错也不排除）；`title_and_abstract.search:!"cat"` — `!` 前缀**直接 400**（"Search filters do not support the ! operator"） |

**强制共现模板**（推荐写法）：
```
filter=title_and_abstract.search:<物种词\|...>,title_and_abstract.search:<技术词\|...>,title_and_abstract.search:<投喂词\|...>
```
三个 `title_and_abstract.search` 用逗号分隔= AND 逻辑，确保被检记录同时包含物种、技术、应用三类词。

**排除词正确用法（V2.3）**：OpenAlex 文本搜索过滤器**不支持任何 API 层排除语法**（`-` 静默失效、`!` 直接 400，实测于 2026-08-10）。排除词一律通过 `harvest_openalex_filtered(exclude_terms=[...])` 参数传入，脚本在**本地**按标题和 inverted-index 摘要包含任一排除词剔除记录；双词短语需完整连续子串才能命中。
